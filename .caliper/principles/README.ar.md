# مبادئ H-OS — نظرة عامة للبشر

هذه الملفات هي المبادئ الأم لمشروع **H-OS** (HiraTechLabs). كل تطبيق داخل H-OS (H-HR وH-Asset وH-Finance ...) يرثها ويضيف إليها ما يخصه فقط. والنماذج الثلاثة في Caliper (Planning وExecution وReview) ملزمة بها.

## الفكرة
- المبادئ مكتوبة بالإنجليزية لأنها تُقرأ بواسطة النماذج ولتوحيد لغة المستودع. هذا الملف هو الشرح العربي.
- كل مبدأ **قاعدة ذرّية** لها معرّف (مثل `SEC-001`) ومستوى (`must` إلزامي أو `should` مفضّل) وطريقة فرض (`lint` أو `arch-test` أو `test` أو `ci` أو `review`) ووسوم.
- النموذج لا يقرأ الملفات كلها. يقرأ `CORE.md` (صفحة واحدة) ثم **Task Brief** يبنيه Planning ويحتوي القواعد المرتبطة بالمهمة فقط.
- القواعد التي تُفرض آلياً (`lint` و`arch-test` و`test` و`ci`) تعمل حتى لو لم يقرأها أي نموذج. والقواعد من نوع `review` هي الأضعف، والهدف تقليلها بمرور الوقت.
- H-OS نظام أعمال متكامل: ركنا المودل المونوثيلي (modular monolith) هو الافتراضي، وحدود ملكية التطبيقات تُفرض، والتواصل بين التطبيقات يمر عبر عقود منشورة وأحداث متدرجة. تقنية الـ backend قيد إعادة التقييم: القرار `DEC-0001` (NestJS) أصبح `proposed`، والقرار `DEC-0008` يقارن البدائل ولم يُعتمد أي بديل بعد، ويُعد أي تضيف في نظام التخطيط والرسوم البيانية بحاجة إلى قرار معلن قبل إدخال مكتبات بصرية إضافية.

## الوراثة
- التطبيق يرث كل قواعد H-OS.
- يستطيع **الإضافة** (بمعرّف يبدأ برمز التطبيق مثل `HR-BIZ-001`) أو **التشديد** (`overrides`).
- **التخفيف** (`relaxes`) ممنوع إلا بقرار (Decision) معتمد وله تاريخ مراجعة.
- أي تغيير في المبادئ نفسها يمر عبر قرار.
